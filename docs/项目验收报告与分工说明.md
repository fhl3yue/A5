## 3. 验收时建议优先展示的内容

1. `/app/` 游客端首页
2. 文本问答
3. 图片上传识别（建议用预存的清晰景点图片演示）
4. 路线推荐
5. 数字人讲解视频
6. 后台状态与日志

如果老师只看一个闭环，建议按这个顺序演示：

```text
游客提问
-> 本地知识库 / RAG
-> 主模型补充
-> 文字首答
-> 语音补充
-> 数字人讲解
-> 后台记录
```

## 4. 两人分工建议

### 你负责：A 端与智能能力

- 项目背景与需求拆解
- 后端架构与数据库
- 本地知识库与 RAG
- GLM-5.1、GLM-4.5V、BAAI/bge-m3
- 事实问答准确率与范围控制
- 管理后台、日志、评测
- 系统稳定性与边界处理

### 队友负责：B 端与展示体验

- 游客端 H5
- 文本、语音、图片入口
- 推荐问题与路线展示
- 数字人舞台、待命层、讲解层
- English 展开与播放
- 反馈、评分、滚动体验
- 手机端适配与视觉效果

## 5. 验收补充口径

- 内部 50 题测试集的 50/50 只用于开发回归，不等于老师最终评测结论。
- 多模态证据来自 `GLM-4.5V` 图片理解，不是把图片当附属装饰。
- 数字人主线是 LiteAvatar sidecar，不是完整 OpenAvatarChat UI。
- 语音链路采用浏览器本地朗读优先 + 服务端缓存兜底，原因是同步生成 MP3 太慢。
- 不相关问题应明确提示当前知识库未覆盖，不再硬套景区模板。

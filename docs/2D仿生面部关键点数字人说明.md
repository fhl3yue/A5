# 2D 仿生面部关键点数字人说明

## 1. 升级目标

本项目当前数字人从“静态/卡通 SVG 角色 + 音频振幅嘴动”升级为“原创 2D 仿生面部 Rig + 口型/表情参数驱动”。目标是更清楚地回应赛题中“数字人能以语音、表情和口型同步的方式进行回答”的要求。

本轮仍然坚持低风险原则：不使用真人肖像，不复刻明星或虚拟偶像 IP，不强依赖 3D、视频生成或 Live2D Cubism 模型。

## 2. 开源项目取舍

- Rhubarb Lip Sync：作为可选口型分析工具。服务端音频生成后，可调用 Rhubarb 输出 `mouthCues` JSON，再由前端按时间轴驱动嘴型。
- MediaPipe Face Landmarker：作为面部关键点和 blendshape 体系参考，不直接引入依赖。
- Kalidokit：作为“关键点到表情参数”映射参考，不作为核心依赖。
- pixi-live2d-display：作为二阶段 Live2D 展示备选，本轮不强行接入。
- Wav2Lip、SadTalker、LivePortrait：偏视频生成或重模型推理，暂不采用。

## 3. 当前实现方式

游客端新增 `bio-face-rig` SVG 层，包含原创半写实导览员头肩像，并按面部区域拆分为：

- 头部与下颌轮廓
- 眉毛
- 眼睛与瞳孔
- 鼻梁
- 脸颊
- 嘴部多口型
- 服饰与导览胸牌
- 面部关键点调试层

前端统一通过 `applyFaceRig()` 驱动表情参数，包括：

- `mouthOpen`
- `mouthShape`
- `eyeOpen`
- `browLift`
- `headYaw`
- `headPitch`
- `smile`

## 4. 口型同步链路

当前有三种口型驱动方式：

1. Rhubarb 口型时间轴
   - 开启 `ENABLE_RHUBARB_LIPSYNC=true` 后，服务端音频生成完成时尝试生成 mouth cues。
   - `/api/chat/audio/{log_id}` 会返回 `lipsync_url`、`lipsync_provider`、`mouth_cue_count`。
   - 前端播放音频时优先读取 `lipsync_url`，按 Rhubarb 的 A/B/C/D/E/F/G/H/X 嘴型切换。

2. Web Audio RMS 兜底
   - 如果 Rhubarb 未安装、未启用或生成失败，前端继续用 Web Audio 分析音频振幅。
   - 振幅越大，嘴巴张开越明显，同时带动头部、眼睛和光效。

3. 浏览器本地朗读节奏模拟
   - 当游客端使用 `speechSynthesis` 本地朗读时，没有服务端 MP3 文件。
   - 前端使用朗读边界事件和节奏定时器模拟嘴型变化，保证首答速度。

## 5. Rhubarb 配置

`.env.example` 中已增加：

```text
ENABLE_RHUBARB_LIPSYNC=false
RHUBARB_BIN_PATH=tools/rhubarb/rhubarb.exe
LIPSYNC_CACHE_ENABLED=true
LIPSYNC_TIMEOUT_SECONDS=12
```

默认关闭 Rhubarb，避免没有安装二进制时影响演示。

如果要启用：

1. 下载 Rhubarb Lip Sync Windows 版本。
2. 将 `rhubarb.exe` 放到 `tools\rhubarb\rhubarb.exe`。
3. 运行检测脚本：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\check_rhubarb_lipsync.ps1
```

4. 在本机 `.env` 设置：

```text
ENABLE_RHUBARB_LIPSYNC=true
```

5. 重启后端。

生成的口型 JSON 会放在：

```text
data/generated/lipsync/
```

该目录属于运行时产物，不进入 Git。

## 6. 答辩说明话术

可以这样说明：

本项目数字人采用原创 2D 仿生面部 Rig。我们参考 MediaPipe Face Landmarker 的关键点和 blendshape 思路，将脸部拆分为眉眼、鼻梁、嘴唇、脸颊和头部姿态等可控区域。语音播放时，系统优先使用 Rhubarb Lip Sync 生成口型时间轴；未启用 Rhubarb 时，前端使用 Web Audio RMS 实时分析声音振幅，驱动嘴型、眼神和头部微动。因此数字人不是简单贴图，而是具备语音驱动口型和表情反馈的 2D 数字人展示层。

## 7. 调试方式

管理端或答辩调试时，可在访问地址后添加：

```text
?debugFace=1
```

在管理端视图中会显示面部关键点层，用于说明关键点绑定思路。游客端默认不显示调试点。
